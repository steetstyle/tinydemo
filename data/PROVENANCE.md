# Data provenance

Every file in `data/` is trace/log input, not our own measurement. Its origin is
recorded here so a thesis reader can re-obtain exactly the same bytes.

## `failing-trace.json`

Synthetic OTLP/JSON trace, generated by `gen_trace.py` (same directory).

- Two services: `Dashboard.API` (client) → `Agency.API` (server).
- One request, `GET /api/agency/{agencyId}/member`, concrete target
  `/api/agency/9f1c/member`, ending in an error (`status` / `http.status_code` 503).
- The route pattern and the handler it maps to are **real**: they were read from
  the example solution (`tiny-pdg-cs route …/Agency.API` → `GETAgencyMembersEndpoint.Handler`,
  `Agency.API/Endpoints/Members/GetAgencyMembersEndpoint.cs:14`).
- Span shape (field names, `kind` values, `scopeSpans` layout) was copied from
  `tinylink/tests/fixtures/otel/error_request.json`, a fixture that the tool's own
  test suite parses.

Validity note (thesis §limitations): the failing route and the analysed source
come from the same solution. That is exactly the *inverse crime* setting — the
trace was constructed against code we then analyse. The demo makes no accuracy
claim; it exists to show the pipeline wiring end to end.

### Parser quirk worth knowing

`http.status_code` is parsed as a JSON **number** (`"intValue": 503`), not as the
string the OTLP JSON spec prescribes (`"intValue": "503"`). The string form makes
`tinylink sdg` fail with `Error: Failed to parse trace`. The generator writes the
number form.

Regenerate:

```bash
python3 data/gen_trace.py > data/failing-trace.json
```

## `otlp-logs-capture.bin`

Byte-identical copy of `tinylink/tests/fixtures/otlp-logs-capture.bin`
(2780 bytes). OTLP/protobuf log payload, 8 records across 2 traces.

- Ingested with `tinylink logs-ingest`.
- The error records read `Agency.API — Handler GetAgencyMembers failed:
  no name for agency 9f1c`, i.e. the log side and `failing-trace.json` describe
  the same synthetic incident. This is deliberate: the demo shows one incident
  across two telemetry signals.
- Records were captured from a local probe (`/tmp/opencode/otlplog/probe`), not
  from a production system. No real user data.

Copy with checksum:

```bash
cp ../../tinylink/tests/fixtures/otlp-logs-capture.bin data/
sha256sum data/otlp-logs-capture.bin
```
